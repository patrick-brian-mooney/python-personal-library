# `make_slideshow.py` Manual
## Guide for Processing Slideshows into Reveal.js slideshows, then hand-editing them

`make_slideshow.py` is a Python script by Patrick Mooney that produces Revaal.js HTML/JavaScript slideshows for web display from various static slideshow formats (currently only OpenOffice/LibreOffice `.odp` files are supported, but eventually at least some others will be). Its primary goal is to extract absolutely all text from each slide and place it into the corresponding slide in the output. It attempts to preserve much of the formatting of individual pieces of text (italic, bold, underline—but *not* font face, font size, or font color). It also tries to preserve the structure of individual text blocks on the original slide. It does *not* attempt to preserve the overall layout of the source slides, because HMLT/CSS?JavaScript formats like Reveal.js use very different strategies for slide layout, and it is not possible to automatically translate layout from other formats to Reveal.js reliably. You should expect that some manual editing will be required on the final output generated by this script.

For the same layout-related reasons, the script extracts images from source files, but doesn't make any attempt to insert them into the destination slideshow. They will have to be added to the destination slideshow by hand. Some guidelines on how to do this are presented later in this manual.

The Reveal.js slideshow assumes that you have a local copy of the Reveal.js resources installed somewhere on the web server from which you will be hosting the slide show. This script also assumes that you have a CSS file that will be applied to the output slideshow somehwere on that web server. Both of these resources are assumed to be at locations that make sense on my machine, but probably not on yours, so you should specify the actual locations using command-line parameters. (#FIXME! We are not yet processing command-line parameters!)

Basic usage: Run `make_slideshow.py` from the directory containing the .odp slideshows you want to convert. It will convert each `.odp` file in that directory to an HTML file. If the slideshow contains embedded images, it will produce a folder called `[slideshow name]_images` and extract the images into that folder; you can then integrate them into the slideshow as you perform the hand-editing that will certainly be necessary. (You can of course also rename and/or move the images on your web server.) Once you've got the slideshow looking the way you want it to look, you can move it into your staging area and upload it to your web server.

## Image inclusion
Images can be included in slides in two ways: as the background image for a single slide, or as an inline block that appears as part of a slide content.

### Inline image integration rules
Use inline images when graphics must sit inside the presentation text flow, shift layout blocks fluidly, or scale dynamically with the content area.

#### Centered image placement
To drop an image cleanly beneath a slide header (or otherwise into an existing slide structure), insert the `<img>` tag immediately preceding the closing `</section>` marker.

```html
<section id="slide-id">
    <h1>Slide Title</h1>
    <ul>
        <li>Bullet content text string</li>
    </ul>
    <img src="Presentation_Name_images/image_asset.png" alt="Descriptive label">
</section>
```

* **Layout Behavior:** The global design stylesheet automatically captures this tag, overrides inline text wrapping (`display: block`), centers the asset horizontally (`margin: 10px auto`), and forces constraints to maintain widescreen viewport aspect boundaries safely.

#### Split-column layouts (with rigid column matrix)
To position text on one side and a graphic asset on the other without vertical stacking, wrap the image and the text content inside a dset of `<div>` elements that use the Flexbox CSS styling rules. 

##### Pattern A: Left image / right text (fixed image scale)

```html
<section id="slide-id">
    <h1>Asymmetric Layout</h1>
    <div style="display: flex; gap: 20px; align-items: center;">
        <div style="flex: 0 0 350px;">
            <img src="Presentation_Name_images/diagram.png" alt="Visual Asset"></div><div style="flex: 1;">
            <ul>
                <li>The text block fluidly grows to sweep across remaining canvas space</li>
                <li>`align-items: center` locks elements along their horizontal midpoints</li>
            </ul>
        </div>
    </div>
</section>
```

* To freeze the image footprint so it never squashes or stretches when the viewport changes size, use a rigid flex basis allocation (`flex: 0 0 [pixels]`).

##### Pattern B: Left text / right image (fluid 50/50 split)

```html
<section id="slide-id">
    <h1>Symmetric Layout</h1>
    <div style="display: flex; gap: 20px;">
        <div style="flex: 1;">
            <ul>
                <li>Content block one</li>
            </ul>
        </div>
        <div style="flex: 1;">
            <img src="Presentation_Name_images/chart.png" alt="Visual Data">
        </div>
    </div>
</section>
```

#### Parameters & constraints
* **Dimension attributes are prohibited:** Do not declare explicit `width="..."` or `height="..."` pixel attributes on the `<img>` element. They enforce a hard physical scale that breaks container flexibility. Manage your boundary footprints exclusively via parent wrappers.
* **Relative paths are mandatory:** All asset references must use relative folder locations pointing straight into the local folder layout sitting alongside the document (e.g., `src="Presentation_Name_images/filename.png"`).

### Images as slide backgrounds
Use background images when graphics must fill the entire bleed window of the viewport layout. It is also possible for text to float over the background image.

#### Backgrounds for individual slides 
use the `data-background-image` attribute directly on the opening `<section>` container tag of an unwrapped presentation line.

```html
<section id="slide-id" data-background-image="Presentation_Name_images/background_graphic.png">
    <h1>Slide Content</h1>
    <p>Text floats cleanly over full-bleed media layer</p>
</section>
```

##### Higher-contrast text shrouding (`.text-overlay`)
To ensure high text legibility over busy background images without reducing the brightness of the background itself, wrap your slide content blocks inside a dedicated structural layout division (`<div>`) assigned to the custom `.text-overlay` class.

```html
<section id="slide-id" data-background-image="Presentation_Name_images/busy_graphic.png">
    <h1>Slide Heading</h1>
    <div class="text-overlay">
        <ul>
            <li>This box draws a crisp, semi-transparent white backing panel</li>
            <li>The background graphic outside this panel stays 100% bright and clear</li>
        </ul>
    </div>
</section>
```

* **Details:** The panel is configured with an accessibility-tested **80% opacity backing value** (`rgba(255, 255, 255, 0.80)`), an integrated drop shadow to provide visual separation from the background image, and customized padding bounds to preserve reading space.


#### Presentation-specific master backgrounds
To apply a persistent master background across *every single slide* in one specific presentation without muddying your shared global CSS stylesheet, embed a localized `<style>` block directly into the `<head>` of that individual HTML document.

```html
<head>
  <meta charset="utf-8">
  <title>Workshop Session Presentation</title>
  <link rel="stylesheet" href="/path/to/resources/css/reveal-custom.css">
  
  <!-- Isolated Master Backdrop Override -->
  <style type="text/css">
    .reveal-viewport {
      background-image: url("Presentation_Name_images/master_background_pattern.jpg") !important;
      background-size: cover !important;
      background-position: center center !important;
      background-repeat: no-repeat !important;
    }
  </style>
</head>
```
